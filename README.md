# uttt — Ultimate Tic-Tac-Toe

Telegram Mini App: сервер, протокол и клиент. Переписан с Node на Rust
под бюджет 132 МБ памяти и урезанный процессор.

## Сборка

    ./build.sh

Скрипт тянет шрифты из npm, жмёт ассеты, генерирует таблицу вшитых
файлов и собирает релиз. Нужны `cargo` и `node`.

## Запуск

    DATA_DIR=/data PORT=80 BOT_TOKEN=... APP_URL=https://your.app/ \
    WEBHOOK_SECRET=... ./target/release/uttt

`ALLOW_GUESTS=1` разрешает игру без Telegram. Вебхук ставится один раз:

    curl "https://api.telegram.org/bot$BOT_TOKEN/setWebhook" \
      -d url=https://your.app/telegram/webhook -d secret_token=$WEBHOOK_SECRET

## Замеры

200 клиентов, 100 партий, ~5900 ходов за 12 секунд:

|                   | Node   | Rust    |
|-------------------|--------|---------|
| RSS в простое     | 73 МБ  | 2.9 МБ  |
| RSS под нагрузкой | 89 МБ  | 4.9 МБ  |
| CPU на прогон     | 0.86 с | 0.07 с  |
| потоков           | 11     | 1       |
| поставка          | ~45 МБ | 1.1 МБ  |

Ход: p50 6 мс, p90 16 мс, p99 26 мс.
Первая загрузка: 9.6 КБ разметки + 98 КБ шрифтов темы.
Смена темы: 0.35 КБ токенов + около 58 КБ шрифтов, один раз.

## Протокол

Дельтовый: ход это `{"t":"m","v":40}` — двадцать байт вместо ~400.
Клиент прогоняет те же правила и сходится с сервером; реконнект
досылает список ходов, а не состояние.

Клиент → сервер: `hello`, `queue`, `cancel`, `move`, `resign`, `invite`,
`join`, `top`, `skin`, `ping`.
Сервер → клиент: `welcome`, `queued`, `start`, `m`, `over`, `gone`,
`invite`, `top`, `skinok`, `err`, `pong`.

## Клиент

Один файл `assets/index.html`. Оформление в CSS-переменных: тема меняется
записью значений в `:root`. Стартовая тема вшита в документ, поэтому
первый экран рисуется без ожидания сети; остальные качаются по
`/t/<id>.json` вместе со своим набором шрифтов `/f/<id>.css`.

Скин — форма `clip-path` и два цвета, четыре байта на игрока; соперник
видит ваш облик. Очередь показывается волной по девяти полям.
Высота строки статуса зафиксирована, иначе смена текста двигала доску.

## Устройство сервера

- однопоточный рантайм, всё состояние в одной задаче-хабе: ни мьютексов,
  ни блокировок, ни переездов между ядрами;
- комнаты в слабе со списком свободных слотов, буферы переиспользуются;
- статика вшита в бинарник и пожата на сборке; woff2 отдаётся как есть —
  повторное сжатие только жгло бы процессор;
- свои SHA-256/HMAC/SHA-1/base64 и мини-JSON: 15 зависимостей всего;
- бот отвечает в теле вебхука, поэтому TLS-клиента в проекте нет;
- рейт-лимит с ценой по типу: ход 1, приглашение 5, таблица рейтинга 10.

## Что исправлено против прежней версии

- ход с индексом вне диапазона подвешивал партию навсегда;
- три ничейных поля в ряд ошибочно заканчивали партию;
- имена игроков попадали в разметку без экранирования;
- сброс рейтингов на диск блокировал цикл событий на каждой партии;
- таблица рейтинга отдавала наружу Telegram ID;
- коллизия кода приглашения уводила чужой инвайт;
- RD росла так, что ветеран становился «предварительным» за девять дней;
- гости заводили постоянную запись в хранилище на каждое подключение.

## Тесты

    cargo test    # 102 теста

Правила и оба прежних бага, эталон Гликмана, векторы RFC 4231 и RFC 6455,
коллизия кодов приглашений, grace-период с возвратом, рейт-лимит,
экранирование имён. Сквозные сценарии проверены в Chromium: две вкладки
играют партию до результата с синхронными досками, ленивая загрузка тем и
шрифтов, смена формы и цвета знака, вход по коду, восстановление партии
после перезагрузки страницы.
